# 今天吃什么 · 命运抽取器

一个把「食堂 + 档口」填进去、让运气替你决定今天吃什么的单页小站。
零依赖、零构建、零后端 —— 双击 `index.html` 就能跑，数据全部留在你自己的浏览器里。

默认预置了一份 **大连理工大学**（凌水主校区）的示例清单：校内各生活区食堂 + 校门口汇源美食广场 +
凌水路/高新商圈等周边热门就餐点，共 **13 个食堂、76 个档口**，
并按教学馆、综一、综二、直角楼、机械楼、东山实验室、本科宿舍、研究生宿舍标好了
**8 个地点**，其中 10 家食堂挂了「离哪近」。
首次进入可以一键跳过直接用它；也可以选「我自己填」，从一份**彻底的空白**开始 ——
那条路上连地点都不预置（不会有「教学馆」这种跟你无关的地名），
食堂、档口、地点全由你自己写，控制台会直接打开等你填。

## 快速开始

**最省事**：直接双击 `index.html`。

**想更稳**（推荐，避免个别浏览器对 `file://` 的限制）：

```bash
cd what-to-eat
python -m http.server 8765
# 打开 http://127.0.0.1:8765/
```

## 两种抽取方式

| 方式 | 抽什么 | 结果 |
| --- | --- | --- |
| **去哪吃** | 抽食堂 | 主选食堂 + 次选食堂（互不重复） |
| **吃什么** | 抽档口 | 主选档口 + 次选档口，并标出各自属于哪个食堂（= 主选/次选食堂） |

「去哪吃」抽完之后，结果里会出现一个可选的 **✨ 顺便决定吃什么** ——
它会在刚抽中的那两个食堂里各抽一个档口，于是「食堂 + 档口」一次定齐。

规则细节：

- 只从**已启用**的食堂/档口里抽，停用的直接不参与。
- **加权抽取**：每个食堂可以设「偶尔 / 常去 / 本命」三档权重，权重越高越容易被抽到。
- **不放回**：主选和次选不会撞车；「吃什么」模式下如果只有唯一一个食堂有档口，会退化成在同一食堂换档口并给出提示。
- **手气值**：每次抽取会算一个 0-100 的趣味评分（越冷门/越小众的食堂越容易冲高），配一句吐槽。
- 点结果卡上的 **🎲 换这一个** 可以只重抽主选或只重抽次选。

## 从哪出发？

舞台上方有一排**出发地**（默认选中「🎲 任意」）。挑一个地点，抽取范围就收窄到
「标了**离这儿近**」的那些食堂；「吃什么」模式下档口也跟着一起收窄。
选中的那条会同时影响三处：顶栏摘要、结果卡上的一行「📍 从 X 出发 · 附近 N 家食堂」、
以及清单星系（射程外的星球会变暗）。

- **默认「任意」** = 整份清单一起来，和之前完全一样。
- **地点可以不止一个归属**：一家食堂能同时挂在「教学馆」「综一」「本科宿舍」下面，
  所以「离得近」是 A 到 B 的多对多关系，不是层级。
- **优雅退化**：万一某个地点底下一家食堂都没挂，不会抽不出来 —— 会自动放宽成整份清单，
  并在结果里明说「清单里没有食堂标了离『X』近，这一次就把整个清单一起抽了」。
  出发地卡片上会显示该地点附近有几家（0 家的会显示成待补状态）。
- **附近优先，不足则放宽**：主选一定来自附近；次选优先也在附近，附近不够时再往后排。
- 结果卡上每家食堂都带一个角标 —— 在附近的显示「离 X 近」，被放宽进来的显示「稍远」。
- 键盘 <kbd>←</kbd>/<kbd>→</kbd> 在出发地之间挪，<kbd>Home</kbd>/<kbd>End</kbd> 跳到两端。

地点本身在控制台 → 「食堂与档口」→ **📍 地点** 里维护：可改名、增删、上下调序。
删掉一个地点时，所有食堂上引用它的「离哪近」标记会一起清干净，不留悬空引用。

## 数据与分享

| 能力 | 说明 |
| --- | --- |
| 自动保存 | 任何改动都会写进 `localStorage`，下次打开自动读取，不用手动保存 |
| 存储位置 | 全在本机浏览器里：清单与设置存 `wte.state.v2`，首次进入的选择存 `wte.seen.v1`（键名里的 `v2` 是历史遗留，schema 已经到 v3 了）。换浏览器 / 换设备 / 清缓存都不共享，也不上传任何服务器 |
| 分享链接 | 整份配置（含地点与「离哪近」）gzip 压缩后塞进 URL 的 `#c=...`（不支持压缩的浏览器自动退回未压缩格式），发给谁谁打开就能看到 |
| 导入 | 粘贴链接 / 贴 JSON / 选文件 / 直接把 `.json` **拖到页面上** |
| 导出 | `导出 .json`（含地点、抽取统计，方便换设备迁移）、`导出 .md`（人肉可读的清单，地点与「离哪近」一并列出） |
| 批量粘贴 | 一次贴一堆：每行一个食堂名，以 `-`、`*`、`·` 或数字开头的算档口；也支持 `食堂 > 档口` 写法；行尾加 `@教学馆、本科宿舍` 就能顺手把「离哪近」一起标上（没对上的地点名会提示出来） |
| 一键操作 | `载入大工示例` / `清空全部` / `重置`，三个按钮挨在一起，但动静不一样 |

**`清空全部` 和 `重置` 不是一回事**：

- `清空全部` 只清清单和地点 —— 主题色、统计、成就、以及「已经来过」的记录都还在，适合换一份清单重填。
- `重置` 会把这台设备上的**一切**抹掉（清单、地点、主题、统计、成就，连「已经来过」的标记一起），
  然后立刻回到最初那道「用示例数据还是自己填」的门 —— 相当于全新的人第一次打开这个页面。
  地址栏里如果挂着一条分享串，也会一并清掉，免得刷新又把它导回来。

> 隐私：所有数据只在你本机浏览器里，不上传任何服务器，也没有任何埋点。

## 自定义

控制台（顶栏「控制台」或按 <kbd>S</kbd>）分三页：

- **外观** —— 主题色（14 个预设 + 取色器 + 随机）、颜色浓烈程度、深空/浅光两套外观、动效强度（全开/精简/关闭）、音效、抽取后是否自动滚到结果。
  改一个主题色，整套色板、光晕、渐变、粒子、卡片描边都会跟着重算。
- **食堂与档口** —— 增删改食堂与档口，支持权重、启用开关、排序、搜索、批量粘贴；
  每个食堂还有一组「**离哪近**」多选按钮，以及底下一个可折叠的 **📍 地点** 面板（增删改名、调序、看每个地点附近有几家）。
- **数据与分享** —— 分享链接、导入、导出、载入示例、清空全部、重置。

### 几个刻意的技术选择

- **不用 ES Module、不用构建工具**。全部是经典 `<script>` + 一个 `window.WTE` 命名空间，
  这样 `file://` 双击打开也能跑，不需要起服务器。
- **没有框架**。状态变更只有一个入口 `store.mutate()`，改完自动存盘并广播，
  跨模块通信走订阅，避免出现「谁改了什么」说不清的情况。
- **颜色全部由主题色推导**。主题色只存一个 hex，运行时换算成 HSL 分量写进 CSS 变量，
  其余颜色（互补色、辅色、光晕、描边、背景）都是 `calc()` 出来的，所以换色不会有漏改的地方。
- **抽取用 `crypto.getRandomValues`**（拿不到才退回 `Math.random`）。
- **导入是宽容的**：缺字段补默认、字段类型不对就忽略、ID 冲突自动去重，
  并在界面上把「修了什么」用提示条讲清楚，而不是直接报错拒收。
- **出发地是一个过滤层，不是新一套数据**（`draw.resolvePool()`）：
  抽取引擎照旧只认「一份食堂池」，出发地负责算出这份池子该缩到哪。
  它返回 `{ primary, applied, warnings }` —— `applied` 表示约束到底有没有生效，
  附近一家都没有时自动退回整份清单并把原因写进 `warnings`。
  于是「带出发地」和「不带出发地」走的是同一条代码路径，只是池子不同。
- **数据模型升到 v3，老数据自动升级**：v2 的本地数据没有 `places` 和 `near`。
  载入时如果发现版本偏低，会拿食堂名字去比对内置的大工示例 —— 对得上的才补上
  地点和「离哪近」，对不上的保持原样，同时提示「已按大工示例补上」。
  这样既不会丢用户自己录的食堂，也不会凭空塞进一堆陌生的楼名。
  导入时 `near` 里的地点既接受 id 也接受**地点名字**，事后统一解析成 id；
  引用了已不存在的地点会被静默清掉，不会留下悬空引用。
- **清单星系的排布是算出来的，不是摆出来的**（`renderGalaxy()`）：
  1. 先量**父级滚动容器**的尺寸（而不是量自己，否则「自己撑高自己」会形成反馈）；
  2. 由「星球外接框总面积 ÷ 椭圆面积」的目标密度 `DENSITY = 0.34` **反推星球直径**，
     再据此算出椭圆半轴 —— 这是「不互相压住」的关键，直径跟着容器和数量一起变；
  3. 用叶序（向日葵）公式撒种子点，然后跑**两两分离松弛迭代**把重叠推开、
     每轮再收回椭圆内，正常情况下 100 轮内收敛；
  4. 万一没收敛，就把椭圆撑高 16% 重试（宁可让面板滚动，也不接受重叠）；
  5. 最后按**实际落点**定容器高度并整体居中。
  随机抖动来自 `hash01(食堂 id)` 而不是 `Math.random()`，
  所以改个主题色触发重渲染时，整片星系不会乱跳。

## 冒烟测试（可选）

`tools/smoke/` 下有一个零依赖的验收脚本：把真实的 `index.html` 装进 iframe，
用**真实点击**跑一遍关键流程，再把页面里的断言抓出来。

```bash
python -m http.server 8765          # 另开一个终端
node tools/smoke/run.js --all       # 全部步骤
node tools/smoke/run.js draw-where follow import --keep   # 指定步骤并保留截图
```

它会自动找本机的 Edge / Chrome（也可以用 `EDGE_PATH` 环境变量指定）。
覆盖：首次引导、本地持久化（同一 profile 连开两次，断言食堂 / 地点 / **出发地**都还在）、
三种抽取、出发地约束与退化、单点重抽、地点编辑器的增删改名与悬空引用清理、
v2 老数据升级、清单星系、分享链接编解码回环、批量粘贴（含 `@地点`）、
主题切换、异常导入、空清单兜底、空白模板（`blank`，外壳是 `blank-persist`）、
重置后重开（`reset` + `fresh`，外壳是 `reset-persist`）。

出发地相关的四个步骤，断言同样是量化的：

| 步骤 | 场景 | 断言 |
| --- | --- | --- |
| `origin` | 选中「教学馆」后抽食堂 | 抽中的两家**全部**挂着 `near` 含教学馆；出发地行与角标都在 |
| `origin-what` | 同上但切到「吃什么」 | 两个档口所属食堂都在附近 |
| `origin-tight` | 临时造一个**没有任何食堂挂着**的地点「荒岛」 | 抽得出来（退化成功）且**一家都不该**算附近，同时必须给出降级提示 |
| `origin-narrow` | 把 iframe 压到 430 宽 | 同 `origin`，验证窄屏下出发地横滚仍可用 |

`places` 与 `legacy` 两步分别验证地点编辑器（改名会同步到出发地线路、
勾「离哪近」会更新计数、删地点会清掉引用）和 v2 → v3 的自动升级（只补名字对得上的食堂）。

`reset` 这一步先造出一身「个人痕迹」（改主题色、选出发地、抽一把、攒成就），
再点面板里的 `重置`，然后逐条核对：引导页回来了、`wte.state.v2` 与 `wte.seen.v1` **都清空了**、
清单回到空白模板、出发地与统计归零、主题色回到默认、结果卡收起，连两个红按钮的**计算样式**
都得不一样（`清空全部` 是描边、`重置` 是实心）。`reset-persist` 再在同一浏览器 profile 里重开一次，
断言它**真的什么都没留下** —— 引导还在、存储仍是空的。这一步同时守着那个容易被忽略的坑：
引导页上还没做选择就关掉标签页，占位数据**不能**被当成「来过」写进 storage。

`blank` 走的是「我自己填」那条路，逐条核对空白模板是不是真的空：模板里的 `places` 为 0、
出发地线路上只剩「🎲 任意」一颗 chip、提示写着「还没有地点」、地点面板展开后 0 行、
食堂恰好 1 条占位并能正常抽出来（结果卡上是「任意出发」而不是某个地点约束）。
`blank-persist` 再重开一次，用 `?canteens=1&places=0` **精确**断言这份空白原样存了回来 ——
防止「老数据升级」之类的逻辑按食堂名字又把大工地标凭空补回去。

> 所有步骤跑完都会打一行 `END:<step>`，`run.js` 把它也算进判定条件。
> 起因是一次真实的翻车：某步的动画 `await` 永不返回，脚本静悄悄停在半路，
> 而「没看到 `MISS` 就算过」的判定把它当成了通过。

其中星系排布有三个专门的步骤，断言是**量化**的而不是靠看图：

| 步骤 | 场景 | 断言 |
| --- | --- | --- |
| `galaxy` | 桌面 1440 宽，默认那份清单 | 相邻中心距 − 半径和 > 0；无越界；二次重渲染落点完全一致 |
| `galaxy-narrow` | 把 iframe 压到 430 宽 | 同上（走 `?vw=430`） |
| `galaxy-many` | 在默认数据上再复制堆到 37 个食堂 | 同上 |

> 这三步都用**当前默认示例数据**，所以示例数据改了它们会跟着变，不需要改测试。

「重叠」是这样算的：取每个星球的**布局盒**（`offsetLeft/offsetWidth`，
不受 inline `rotate` 影响）算两两 `中心距 − (r1 + r2)`，出现负数就判定 `VERDICT=SQUEEZED`，
`run.js` 会把这个步骤标成 FAIL。

## 数据来源

默认示例数据依据 2025 年网络公开信息整理（学校官网食堂介绍、校友评价、公开地图/点评数据），
并由使用者本人逐条校正过口味、窗口与价格。仅供演示与起步 ——
口味和窗口都会变，欢迎在控制台里按自己的实际情况改。

地点的划分也照这个原则来：教学馆 / 综一 / 综二 属主校区教学区，直角楼是综合楼西侧那座八角楼，
机械楼与东山实验室在 A3 区东山片区，本科宿舍对应西山生活区、研究生宿舍对应北山与博留公寓。
「在水一方西餐厅」是那个西餐厅的老名字，实际开在博留公寓 2 号楼（东山片区），
所以它的「离哪近」挂的是东山实验室一带。
